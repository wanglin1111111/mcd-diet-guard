# MCP 调用链路与降级策略

## 涉及的工具

| 工具 | 在本 Skill 中的角色 | 必需性 |
|---|---|---|
| `list-nutrition-foods` | 营养数据主干，一次返回常见餐品营养成分 | 必需 |
| `query-meals` | 门店在售菜单与餐品编码，补齐主干未覆盖的餐品 | 条件需要 |
| `query-meal-detail` | 配料组成与可替换选项——**改配方案的唯一来源** | 给改配时必需 |
| `now-time-info` | 确认当前时间，用于判断「今日」相关活动 | 可选 |
| `campaign-calendar` | 当月活动日历，补充活动信息 | 可选 |

## 标准调用链路

```
用户诉求（含人群特征）
   │
   ├─→ list-nutrition-foods ──→ 命中目标餐品？
   │                              │
   │                        否 ──┴─→ query-meals（取餐品编码）
   │                                       │
   │                          需要改配 ─────┴──→ query-meal-detail
   │                                       │
   │                                  组装 payload.json
   │                                       │
   │                          nutrition_guard.py 核算
   │                                       │
   └──────────────────────────────→ 按「前置结论」顺序输出
```

★ 判据：不要为了「更全面」把所有工具都调一遍。
  `campaign-calendar` 返回的活动信息**不能当营养依据**，
  用户没问活动就不该调——省下的调用次数留给限流余量。
  反例：每次点单都先查活动日历，属于无谓消耗（限流 600 次/分）。
  触发词：调试时想「多调点工具看看」。

## 降级策略

| 情况 | 应对 |
|---|---|
| `list-nutrition-foods` 未覆盖目标餐品 | 用 `query-meals` 取该门店在售清单；若仍无营养数据，明确告知「该餐品营养数据未获取到」，**不估算** |
| `query-meal-detail` 返回无配料 | 只给阈值判定，明确说明无配料明细故无法给改配方案 |
| MCP 返回缺少 `sugars_g` / `satfat_g` | 该项阈值检查自动跳过，输出中不出现该项——不当作 0 通过 |
| `list-nutrition-foods` 返回缺少某营养项 | 该项密度计算为 0，脚本跳过相关提示 |
| 返回 401 | Token 无效/过期，提示重新申请 MCP Token |
| 返回 429 | 触发限流，降低频率；串行调用而非并发 |

★ 判据：降级必须**说出来**。用户需要知道「没拿到数据」和「数据没问题」的区别——
  静默跳过会让用户以为那项已评估通过。
  反例：MCP 没返回糖数据，输出里就不提糖，用户以为糖没问题。
  触发词：字段缺失、没返回、null。

## Token 与配置

MCP 配置见仓库根目录 `mcp-config.example.json`（仅环境变量占位符）。
接入步骤见主 README。

★ 判据：真实 Token 只放本地 `~/.workbuddy/mcp.json` 或环境变量，
  **绝不写进仓库任何文件**，包括示例文件与文档截图。
  反例：README 里贴「方便大家复制」的真实 Token——违反活动规则的信息安全声明。
  触发词：配置、token、接入。

## 速率

每个 Token 每分钟最多 600 次请求。
单次膳食核算正常调用 2–4 次工具，远低于限流；
除非为测试并发，否则无需特殊处理。
